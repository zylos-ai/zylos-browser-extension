# 浏览器自动化能力升级 TODO

日期：2026-09-07。状态：已接入 agent-browser MCP，补充截图与可视光标；本轮优先完成第 5 步中的专用工作标签隔离和彩色标记。暂缓成功率等统计。各阶段剩余条目不因接入第三方引擎而自动视为完成。

目标：参考用户备份的 ChatGPT 扩展中可确认的定位、等待、诊断和任务管理设计，将当前“能操作浏览器”提升为“稳定完成整件任务”。保留现有双项目架构，不照搬对方的本地连接方式，也不将包内接口的存在视为完整产品能力的证明。

本文件集中记录跨项目工作。文档放在浏览器插件中，不代表所有 TODO 都由插件实现。复选框仅在实现和验收完成后勾选。

## 代码归属

| 项目                                | 负责什么                                           |
| ----------------------------------- | -------------------------------------------------- |
| 浏览器插件：zylos-browser-extension | 找元素、观察页面、执行动作、等待页面状态、操作界面 |
| Channel：zylos-browser-channel      | AI 工具定义与说明、命令转发、设备路由、任务状态    |
| Agent 接入层                        | 把观察结果交给模型、继续决策、验证结果后回复       |

前几个阶段主要修改插件和 Channel；涉及模型上下文、最终回复约束时，再评估 Core 的最小接入改动。不新增 Gateway，不为了补循环另建一个 Agent。

## 第 0 步：先改善顺滑度，保留必要回归

目的：先解决可确认的页面跳动和操作反馈问题，并保证现有操作与停止功能不回退。暂不建立成功率统计或固定模型的任务对比系统；保留后续建立评测基线的计划。

- [x] 保留现有配对、授权、点击、填写、导航、停止测试。
- [ ] 增加模拟网页：延迟加载、同名按钮、遮挡弹窗、保存失败、点击后新开标签。
- [ ] 后续再做：记录任务成功率、工具调用次数、耗时、误操作和重复提交。
- [ ] 后续再做：用固定任务和相同模型设置，对比改动前后。

本轮顺滑度修复：

- [x] 点击和输入使用最小必要滚动，避免把已可见元素强制移到屏幕中央；聚焦输入框不再次滚动页面。
- [x] 移除固定 180ms 的鼠标预览等待；首次出现、同位置和减少动态效果模式直接就绪。
- [x] 鼠标移动按动画完成回执继续，支持取消和有上限的等待；保留真实操作前的位置、焦点和授权校验。
- [ ] 用户体验确认：区分视觉生硬与 Agent 每一步之间的长停顿，再确定下一轮优化范围。

以上不等于模型推理变快，也不代表第 0 步所有模拟场景已经补齐。没有为隐藏等待而自动批量执行写操作。

回归覆盖：首次光标出现、同位置预览、减少动态效果、移动完成、动画取消/超时、停止时禁止后续点击，以及可见元素的点击/输入不改变页面滚动位置。当前未进行真实模型的成功率或耗时统计。

验收：每个场景都有可检查的最终页面状态，而不是只看机器人是否回复“完成”。涉及真实 Agent 的测试须显式授权，不混入无副作用的日常单测。

## 第 1 步：整理 AI 侧工具契约

修改：Channel 为主，插件同步协议。

- [ ] 在 Channel 建立集中维护的工具清单：名称、说明、参数、返回结构、错误类型。
- [ ] 从这份清单生成或校验 CLI 帮助和 Skill，避免三处描述不一致。
- [ ] 明确哪些工具只读，哪些会修改页面；定义超时和取消行为。
- [ ] 连接时交换协议版本和能力列表，旧插件不支持的命令不下发。
- [ ] 两端维护契约测试，不跨项目直接引用源码。

验收：AI 能明确知道工具怎么用；无效参数在执行前被拒绝，新旧版本不匹配时有清晰提示。

先保留现有 Skill + CLI。以后需要原生 tools/MCP 时，复用同一份契约，不同时维护两套定义。

## 第 2 步：补观察和等待

修改：插件执行器 + Channel 工具入口。最高优先级的行为改进。

- [x] 增加统一的 observe：返回当前 URL、标签、导航/授权版本、页面结构、元素 refs 和当前视口 PNG。
- [ ] 增加有超时限制的等待工具：等待 URL、文字、元素出现或消失。
- [ ] 导航、点击等关键动作支持附带操作后的新观察。
- [ ] 区分“命令已执行”和“期望页面状态已出现”。
- [ ] 等待期间能够立即响应停止、断线和窗口关闭。
- [x] 接通截图读取路径：Channel 保存私有 PNG 并提示调用 Codex view_image / 图片读取工具；Skill 指导关键动作后观察和看图。仍需真实本地 Agent 任务验证其调用行为。

本轮已实现与验证的范围见 [截图辅助操作](SCREENSHOTS.md)：联合观察、图片权限/保留期、加载中检查、超限、停止/切页、observe-v1 旧客户端能力门控、模拟保存成功/失败页面。没有每个写命令自动附图，没有通用条件等待工具，也没有新增 Core 任务状态机。上面的等待、动作附带观察和任务强约束项仍未完成。

验收：搜索结果延迟出现时能等到；保存失败时能看到错误；等待期间点击停止不会继续操作。

不要统一改成“每一步截图”或“固定睡两秒”，应该等具体状态。

## 第 3 步：补可靠定位和失败诊断

修改：插件定位模块 + Channel 工具参数。

- [ ] 保留当前 ref 定位。
- [ ] 增加按角色、名称、标签定位，例如“名称为保存的按钮”。
- [ ] 支持限定区域，例如“客户信息表单里面的保存按钮”。
- [ ] 执行前检查可见、可用、可交互，以及是否被遮挡。
- [ ] 零匹配或多匹配时返回候选摘要，不默认点击第一个。
- [ ] 失败时返回原因和必要的新观察：过期、遮挡、禁用、多个匹配等。
- [ ] 允许重新观察、重新定位；不自动重放结果不明的提交操作。

验收：页面上有两个“保存”时不会随便点；元素重新渲染后有恢复路径；超时不会造成重复提交。

## 第 4 步：建立任务级生命周期

修改：Channel 为主，插件和 Agent 接入层配合。

先行小修复：普通浏览器 Channel 答复会等待 finish 释放调试连接，保留窗口授权，下一次工具按需连接。工具忙时不提前收尾。此修复不是任务 ID 生命周期，也不证明业务目标已完成；下列项目仍待实现。

- [ ] 增加任务 ID、回合 ID，与设备、授权会话和命令关联。
- [ ] 定义状态：执行中、等待用户、成功、失败、已取消。
- [ ] 设置任务级时间和步骤上限，避免无限循环。
- [ ] 用户停止后，拒绝该任务继续下发动作，而不只是取消当前命令。
- [ ] 断线后标明哪些操作结果未知，不直接自动续跑写操作。
- [ ] 为常见任务定义完成证据，例如保存提示、详情页内容、目标记录。
- [ ] 最终结果区分“已验证完成”“未完成”“需要用户处理”，避免把点击成功当作业务成功。

验收：机器人不能仅凭“点了保存”就标记创建成功；取消任务后，后续迟到的命令不会继续执行。

任务状态也不能凭空判断业务成功，仍需要实际页面证据。

验收：新功能覆盖真实业务场景，同时不扩大到未经授权的窗口、文件或数据。

## 每一步共同的发布要求

以下检查需要每阶段重复执行，不是完成一次就永久豁免：

- 两个项目独立构建，协议测试和浏览器回归通过。
- 旧客户端不兼容时明确提示，不静默失败。
- 日志能关联任务和命令，但不记录凭据或默认保存完整敏感页面。
- 不出现跨窗口误操作、停止后继续执行、重复提交等回归。
- 先验证模拟页面，再经授权测试实际业务网站。
- 保持既有配对、用户授权和敏感操作确认边界；网页内容不能授予权限。
