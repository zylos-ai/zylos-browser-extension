# Zylos Browser Privacy Policy

Last updated: October 20, 2026.

This policy describes Zylos Browser, the Chrome extension maintained in the [zylos-ai/zylos-browser-extension project](https://github.com/zylos-ai/zylos-browser-extension). It includes the optional diagnostics feature in the current source; diagnostics requires a compatible extension and Remote build.

## How Zylos Browser works

Zylos Browser lets you chat with a Zylos Agent and request browser tasks. You configure the Relay URL and connection Key. The extension sends task-related information to that Relay and Agent. The extension does not provide a built-in hosted AI account or automatically route your conversations to a developer-operated AI service.

Your Relay operator, Agent operator, and any AI model or tool providers used by your Agent may process data under their own policies. Their identities depend on the services you configure; check those services before connecting.

## Information the extension handles

- **Connection settings and identifiers.** Your Relay URL, authentication Key, connection preferences, a randomly generated browser-installation identifier, and connection/task identifiers are used to authenticate and route requests. The installation identifier is not obtained from your Chrome account and is not your name or email address.
- **Messages and files.** The messages you send, Agent replies, selected-text quotations, files you attach, and attachment metadata are used to carry out the conversation or task. Images may have small local previews.
- **Current-page context.** Sending a message normally includes the active page's title, URL, scroll position, the text, link addresses, button names and form-field labels currently visible in the window, and a list of the page's headings. The automatic extractor omits input and editable-field values. The Agent can request more of the page's text. Restricted pages may be unavailable.
- **Browser-task observations.** For a requested task, the extension can read page text and accessibility/DOM information and capture screenshots. It can process navigation, element, viewport, and operation results so the Agent can decide the next step. Page observations can contain personal information that is visible on the page.
- **Task activity.** The extension keeps a bounded local activity history, such as operation names, timing, status, and short target hints. When supported by your Remote, it also receives public Agent progress messages and limited tool activity from the task's Agent session. Accepted decision summaries are included in this history. Hidden model reasoning is not collected for this display. During a task it also observes network request identifiers and timing to determine whether a page has finished loading; this readiness tracker does not retain request headers or response bodies. This supports browser-task execution, rather than general browsing analytics or a recording of everything you type.

- **Optional diagnostics.** Diagnostics is off by default. When you enable it in extension Settings, the extension records allowlisted task, operation, control, connection and runtime events. Records include timestamps, sequence numbers, severity, source context, predefined methods/reasons/error codes, and locally generated task/operation numbers. Background and sidepanel console calls contribute severity and argument counts only; runtime errors contribute safe error classes/codes, not messages or stacks. Your configured Relay and Agent can request and export these records, the actual extension version, and capture completeness metadata. Diagnostic records do not include page text, URLs, input values, cookies, connection Keys, request/response bodies, or arbitrary console/error messages. Your Agent cannot turn this setting on remotely.

The extension has no separate registration form requesting your name, email address, age, postal address, or government identification. It does not request device geolocation or include advertising or third-party analytics SDKs. Content you choose to send, or that appears in a task page or screenshot, may itself contain personal or sensitive information.

## How information is used and shared

Information is used to connect to your configured Relay and Agent, answer messages, perform requested browser tasks, display task activity and previews, and restore local preferences and recent conversation history.

Messages, original attachments, selected text, page context, and task observations may be transmitted to your configured Relay and Agent. When your Agent uses external models or tools, those services may receive the information needed for their operation. Browser actions such as submitting a form also send information to the website involved in that action.

The extension does not include a mechanism that sells user data or sends it to advertising services. It does not use user data for advertising, creditworthiness decisions, or lending. Data use and transfers through the extension are limited to its stated user-facing functionality. Zylos Browser's use of information received through Chrome APIs adheres to the Chrome Web Store User Data Policy, including its Limited Use requirements.

## Storage, retention, and deletion

**Detailed local diagnostics is a separate opt-in.** It captures bounded console strings and Error messages/stacks from the extension background and sidepanel, plus handled browser-operation errors. It does not subscribe to webpage consoles or DevTools logs. Ordinary objects, functions, symbols and bigints are omitted and marked incomplete. Error string data fields are read directly; Chrome's cached native stack getter is allowed only for known native Error prototypes with default formatting and no name/message accessors. Custom getters, custom stack formatters and toJSON methods are not deliberately invoked. Prototype/descriptor inspection can trigger Proxy reflection traps, so this is best-effort diagnostic instrumentation, not a sandbox for hostile JavaScript objects.

While enabled, detailed capture also records CDP method names, call IDs, elapsed time, success/error status, debugger attach/detach and bounded target presence checks. Target identifiers are replaced with capture-local opaque numbers. This metadata excludes command arguments and result values. Native errors still pass through the text rules below and may contain private information.

The local preview packages these records into an incident bundle. It retains at most 256 protocol task/action correlations and eight incidents for operation errors, debugger detachment or control loss. Each incident reports available records in a 30-second-before and two-second-after window, with explicit capture gaps. The bundle includes connection/control state at the trigger and at preview time; a stored tab-group reference does not prove the group still exists. Optional independent, read-only checks of the permitted, pinned top document report visibility, readiness, HTTP/HTTPS category, bounded iframe count, focused element category and input disabled/read-only flags. They never read page text, input values, URLs or screenshots. Checks do not delay or retry browser actions and may finish too late for a true pre-incident observation; timestamps and gaps disclose this. Terminal control loss starts no new page check. Extension and Remote clocks are not assumed aligned. No bundle establishes a root cause or reconstructs missing history.

A read-only observer may run in the isolated world of the currently controlled, permitted top-level document, including a borrowed tab. It records iframe additions/removals/src mutations using document-local opaque numbers, protocol categories, and observation timestamps; it does not export iframe URLs, extension identities, page text or input values. It does not inspect iframe documents or shadow roots. Injection is pinned to the verified document and stops on scope changes, disable or expiry. Limits are two minutes per probe, 256 iframe IDs, 512 events, 64 buffered mutations and bounded scanning. Limit/unavailable/expiry statuses identify capture gaps. Pending records may drain after control ends while the same consent, document and task generation remain valid; no browser action is resumed. The observer does not bypass denied access.

Detailed records remain in background-worker memory for at most ten minutes, 1 MiB and 1,000 records. Overflow evicts oldest records and reports drop counts; serialization limits and reported panel transport losses are recorded. Capture starts partway through an existing runtime and cannot reconstruct previous events. A panel closing, a process crash or failed loss reporting can lose additional events. Disable, expiry, connection-setting changes or worker restart clear the capture; it is not automatically enabled again.

Detailed text may contain private data from extension operations. The capture removes the configured connection Key and recognizable credential patterns, and removes credentials/query/fragment parts of HTTP URLs. These rules cannot identify all secrets or personal information. Review the local JSON preview before explicitly downloading or sharing it. Download uses the exact preview bytes and displays their SHA-256; files include capture/runtime identifiers, timestamps, extension version, a unique build identifier and available source-commit/dirty metadata. The metadata-only `diagnostics.get` interface never returns these detailed records. The separate one-time sharing interface described below requires additional local authorization. Disabling capture cannot retract a file already downloaded or copies you explicitly shared.

Connection settings, the installation identifier, language preferences, recent chat history, bounded Agent progress history, attachment metadata, small image previews, and task-recovery information are stored in the extension's local storage in your Chrome profile. The extension uses local storage, not Chrome's sync storage, for these records.

With a compatible Remote, the live background worker temporarily retains unacknowledged task requests, additional owner messages, and completion receipts in memory so a brief transport interruption does not lose them. These frames can include the original message, attachments, page context, and operation results already needed for the task. The queue is limited to 64 frames, and disconnected-task recovery expires after at most two minutes. Acknowledgement removes the queued frame; task cancellation drops pending request/input frames, and configuration changes clear the queue. Recovery does not add persisted copies of these payloads and does not survive a worker, browser, or Remote process restart. Existing local chat history and a bounded recovery-failure notice remain subject to the retention controls above.

The diagnostic preference is stored locally. Diagnostic records are kept separately in Chrome extension session storage, limited to 1,000 events and 256 KiB, and records older than 30 minutes are excluded when the buffer is read or updated. Capture identifiers, local counters, partial-capture and restart/loss metadata accompany that buffer. Enabling diagnostics during a task starts a new partial capture and does not recover earlier events. Browser-session storage is not a permanent log archive. Turning diagnostics off clears the local buffer; changing the Relay URL or connection Key also disables diagnostics and clears it before saving the new recipient. The diagnostic retrieval endpoint does not create a separate persistent log archive on Remote. Your Agent or other tools may retain or export a fetched copy; turning the switch off cannot retract copies already returned to those services.

Original attachment files are not retained in local chat history. Zylos Browser Remote 0.10.0 writes task-owned temporary attachments and screenshots on the Agent host and attempts to delete those files when their task ends. A process crash or filesystem failure can prevent that cleanup. This cleanup does not delete your original local files or independent copies, conversation records, logs, or backups made by the Agent, Relay deployment, model providers, or other tools.

Use **Clear chat** to remove the extension's local conversation history and associated stored previews. You can disable the connection in Settings and remove the extension through Chrome to remove its extension-local stored data. Deleting local history does not delete records already held by your configured services; contact those service operators for their retention and deletion controls.

## Connection security and your choices

Use a trusted Relay and Agent. Remote connections should use `wss://`; local development can connect to a service on the same machine using `ws://127.0.0.1`. The current extension also accepts user-entered `ws://` endpoints, which are not encrypted in transit, so do not use an unencrypted remote endpoint for sensitive data.

The connection Key is stored in Chrome extension local storage for reconnection; the extension does not add its own encryption layer to that stored value. Protect access to your Chrome profile and revoke or rotate a Key through your Relay operator when it is no longer needed.

Before sending a message, consider the current page context and any selected text or attachments. You can remove a quoted selection or attached file before sending, stop an active task, or disable the Relay connection. Stopping a task does not retract data already transmitted.

## Changes and contact

Changes to this policy will be published with the project. For questions about the extension or this policy, contact the project maintainers through the [project support page](https://github.com/zylos-ai/zylos-browser-extension/issues). ## Optional one-time detailed diagnostic sharing

Detailed capture remains local by default. In the extension settings, a user can prepare and inspect a fixed JSON snapshot, its SHA-256 digest, and the currently configured Remote recipient. A separate unchecked consent control and authorization button permit one retrieval of that exact snapshot. Future log events are excluded. This transfer is available only over WSS.

The Remote service, its operator, the Agent and the Agent's configured AI provider may receive and retain the diagnostic text. Text can contain sensitive information despite pattern redaction. Their retention policies apply to received copies; the extension cannot delete them. No sharing authorization is inferred from enabling local capture.

Authorization expires within two minutes, or when capture expires, whichever comes first. Capture disable, configuration changes, disconnect, or explicit revocation invalidate it. Authorization is consumed before sending a response. A lost response may therefore prevent retrieval; retries do not automatically authorize another transfer. Raw snapshots are not included in general browser state, chat, or metadata diagnostics.
