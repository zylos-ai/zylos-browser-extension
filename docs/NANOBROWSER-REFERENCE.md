# NanoBrowser 参考与当前执行设计

本项目采用插件控制执行循环、远端 Agent 提供决策的结构。Remote 将远端 Agent
适配为请求与决策接口，浏览器任务规则和工具实现都在插件内。

可借鉴的方向是让执行器承担确定性的工作：

- 校验整批动作，顺序执行已知表单编辑；导航或页面变化后重新观察。
- 动作后自动返回状态，减少 Agent 为读取快照和标签页单独做决策。
- 保存简短的已确认事实，使用最新页面证据，不跨导航复用 ref。
- 根据目标是否达成决定结束，避免为了确认而反复修改页面状态。
- 任务异常时保留已完成动作的信息，不自动重放输入。

这些原则体现在 [browser-loop.ts](../utils/browser-loop.ts)、
[browser-round.ts](../utils/browser-round.ts) 和 [decision-guide.md](../agent/decision-guide.md)。

当前 Agent 运行时仍保留自己的会话历史；插件的短记忆不会删除远端会话中的历史输出。
读取结果会限制体积，截图通过图像附件处理。研究类任务仍应按覆盖范围、来源证据和
输出质量评估，不能用少量操作成功代替整项任务完成。

性能比较应记录同一代表任务的首个动作时间、总耗时、模型决策轮次、浏览器执行次数、
观察输出体积、截图次数、重试次数和完成率。Monitor 能提供部分执行证据；
模型耗时和 token 消耗需从 Agent 侧实际轨迹取得，不能仅凭浏览器动作耗时推断。
